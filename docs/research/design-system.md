## Question

How should on-budget build and enforce one strict, documented design system across the web, iOS, watchOS and macOS apps, with light and dark themes (plus increased contrast), with ownership and visibility shown for households that configure their sharing, prototyped in Figma or Claude Design, under the owner's stack constraint: one UI codebase shared by the iPhone, Mac and web apps, plus a native SwiftUI watch app ([`PRODUCT.md`](../../PRODUCT.md) Stack, [ADR 0002](../adr/0002-one-ui-codebase-native-watch.md))? [`cross-platform-ui-stack.md`](cross-platform-ui-stack.md) settles the framework with strategy B (medium confidence): Expo (React Native) for the iPhone, web and Mac apps, react-native-web in browsers, Unistyles 3 for styling. This note designs for B, and says where E, its fallback (one web app in native shells), would differ.

## TL;DR

1. **Make code the source of truth: DTCG 2025.10 token files in the repo, in three tiers, behind one resolver.** The [DTCG format is stable (2025.10, 2025-10-28)](https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/) and defines Format, Color (14 color spaces, OKLCH and Display P3 included) and Resolver modules. Use one resolver with two modifiers: `appearance` (light, dark, light-HC, dark-HC) and `platform` (ios, macos, watchos, web). Generate everything with **Terrazzo 2.10**, the only generator compared here with full 2025.10 and resolver support ([changelog](https://github.com/terrazzoapp/terrazzo/blob/main/packages/cli/CHANGELOG.md)). Its lint and its Swift plugin see only the default permutation, so add a script that checks all 16, and small in-repo plugins for what B needs: Unistyles themes for iOS and the web, `tokens.css`, motion presets for SwiftUI, Reanimated and CSS, the watch's asset catalog and constants, DESIGN.md and Figma JSON. Fallback: Style Dictionary 5.8, run once per permutation. **Confidence: high on the format, medium on Terrazzo.**
2. **Same semantics everywhere, not pixel-identical apps.** Components live once in the React Native package, drawn with UIKit views on the iPhone and by react-native-web in browsers, plus a small SwiftUI set for the watch and widgets ([ADR 0002](../adr/0002-one-ui-codebase-native-watch.md)). On iOS, surface, label and separator roles are `PlatformColor` system colors and the other roles `DynamicColorIOS` with four variants; Unistyles passes both through ([source](https://github.com/jpudysz/react-native-unistyles/blob/main/packages/unistyles/cxx/common/Helpers.h)), so UIKit switches appearance, contrast and elevation itself. react-native-web 0.21.4 has neither API ([exports](https://github.com/necolas/react-native-web/blob/0.21.4/packages/react-native-web/src/index.js)), so every role also gets explicit web values in all four appearances, which CSS media queries in a generated `tokens.css` switch. Use system fonts (SF Pro and SF Compact on Apple, `system-ui` on the web). The web app runs "on any computer" ([PRODUCT.md](../../PRODUCT.md)), where `system-ui` is Segoe UI, Roboto or another OS font, so test the web ramp against those fonts or bundle one OFL face. Apple's SF fonts may not be self-hosted on the web ([license](https://developer.apple.com/fonts/)), and SF Symbols are licensed only for Apple-platform apps ([Xcode and Apple SDKs Agreement §2.10](https://www.apple.com/legal/sla/docs/xcode.pdf)). So use SF Symbols on Apple builds, Lucide on the web, and a semantic icon map between them. **Medium-high.**
3. **Money never relies on color alone.** Every amount carries its sign from the locale formatter. Expenses stay neutral; income gets a plus sign plus color; over-budget gets a status color plus a glyph and words. Charts use position, pattern and direct labels. This follows [WCAG 1.4.1](https://www.w3.org/TR/WCAG22/) and Apple's ["Differentiate Without Color Alone" criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/differentiate-without-color-alone-evaluation-criteria/). Gate contrast on WCAG 2.2 AA in all four appearances, and aim for 7:1 on custom text pairs, as Apple advises for every appearance ([HIG Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)); APCA stays advisory, because WCAG 3 has no contrast algorithm yet ([WD 2026-09-10](https://www.w3.org/TR/wcag-3.0/)). **High.**
4. **One spec file per component is the contract.** Generate the TypeScript and Swift variant and state enums from it, so an implementation that misses a variant fails to compile. Documentation: Storybook 10.6 as the hub, embedding watch and widget snapshots (swift-snapshot-testing), with DocC for the watch's Swift API. **Medium.**
5. **Enforce mechanically.** Component APIs accept tokens only. Lint bans raw values: ESLint selectors inside Unistyles' `StyleSheet.create(theme => …)`, which `react-native/no-color-literals` can't see because it reads only an object-literal argument ([rule source](https://github.com/Intellicode/eslint-plugin-react-native/blob/master/lib/util/stylesheet.js)), and SwiftLint custom rules on the watch. stylelint and Tailwind apply only under E. CI regenerates the tokens and fails on drift. Visual regression runs Playwright 1.65 on the react-native-web build, Maestro screenshots of the iOS app and swift-snapshot-testing for widgets over theme × contrast × text size × locale, on GitHub-hosted macOS runners: no self-hosted runner ([factory](factory-ci-quality.md) TL;DR 1). Accessibility gates: a contrast script over every permutation (Terrazzo's `a11y/min-contrast` checks only the default one), axe-core 4.14 and `performAccessibilityAudit()`. **Medium-high.**
6. **Prototype in Claude Design; keep Figma optional and downstream.** Claude Design ingests the repo, prototypes in HTML and hands off to Claude Code ([support](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)), but it renders web, not native UI. It is on every Claude plan; the design systems `/design-sync` builds are in beta, on Pro and up ([setup](https://support.claude.com/en/articles/14604397-set-up-your-design-system-in-claude-design)). Figma Professional ($16 per Full seat per month, billed annually) adds variable modes, library publishing, Dev Mode and Code Connect; Apple's UI kits are free Community files. Without Enterprise ([Variables REST API](https://developers.figma.com/docs/rest-api/variables/)), code→Figma token sync is a manual JSON import (sRGB only) or agent-driven, and Code Connect covers one framework: React, which includes React Native. Figma's code to canvas imports Claude Design HTML as flat layers. **Medium.**
7. **DESIGN.md is a generated, agent-facing view, not the source.** Its format is `alpha` and has no light/dark modes yet ([issue #13](https://github.com/google-labs-code/design.md/issues/13); PR #128 open). impeccable 4.8 reads DESIGN.md, but with `PRODUCT.md` at `Platform: adaptive` it skips its automatic detector hook, web files included, and declines `generate`; only `web` turns the hook on. Its manual `impeccable detect` still runs, so CI scans the web package with it. **High.**
8. **Ownership and visibility are foundations too.** Couples lack attribution inside the plan, and privacy ([budgeting-products](budgeting-products.md) TL;DR 3), and `PRODUCT.md` makes sharing configurable and data "private by default". So: six member color slots with four variants each, a joint role and a test-household role, plus `MemberAvatar`, `MemberChip` (the owner chip), `VisibilityBadge` (Honeydue's three levels: everything, balances only, nothing), `SplitBreakdown` (who paid, each share, the expected reimbursement), `ScopePicker`, `HouseholdSwitcher` and a persistent `TestHouseholdBanner`. Initials, names, glyphs and words carry identity; member colors only reinforce them (§2.11). **Medium.**

## 1. Token source of truth

### 1.1 DTCG status

- **Stable since 2025-10-28.** Version 2025.10 is a Final Community Group Report with three modules: [Format](https://www.designtokens.org/TR/2025.10/format/), [Color](https://www.designtokens.org/TR/2025.10/color/) and [Resolver](https://www.designtokens.org/TR/2025.10/resolver/). No newer version exists, only a living draft ([TR index](https://www.designtokens.org/technical-reports/)). It is "not a W3C Standard nor … on the W3C Standards Track", but "considered stable" ([Format report status](https://www.w3.org/community/reports/design-tokens/CG-FINAL-format-20251028/)). Named reference implementations: Style Dictionary, Tokens Studio and Terrazzo ([announcement](https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/)). **High.**
- **Format.** Types: `color`, `dimension`, `fontFamily`, `fontWeight`, `duration`, `cubicBezier`, `number`, plus composites `strokeStyle`, `border`, `transition`, `shadow`, `gradient` and `typography`. `dimension` units are **only `px` or `rem`**, as `{ "value": 16, "unit": "px" }`; `duration` units are `ms` or `s`. Aliases are `{group.token}` or a JSON-pointer `$ref`. Groups support `$extends`, `$root`, `$deprecated` and `$extensions` (reverse-domain keys, preserved by tools). File extension `.tokens` or `.tokens.json` ([Format](https://www.designtokens.org/TR/2025.10/format/)). There is no `pt` unit: treat `px` as points on Apple (judgment).
- **Color.** `{colorSpace, components, alpha, hex}` with 14 spaces, including `oklch`, `display-p3` and `srgb`. `hex` is the only defined fallback, and gamut mapping is left to tools ([Color](https://www.designtokens.org/TR/2025.10/color/)).
- **Resolver.** A `.resolver.json` lists `sets`, `modifiers` (each with `contexts` and an optional `default`) and a required `resolutionOrder`. Aliases resolve after merging, and the number of outputs is the product of the context counts. The spec's own example models `light`, `lightHighContrast`, `dark` and `darkHighContrast` ([Resolver](https://www.designtokens.org/TR/2025.10/resolver/)).

### 1.3 Tiers, modes and names

- **Primitive** (`ref.*`): OKLCH ramps with `hex` fallbacks, the space scale, radii, durations and font families. Never referenced by app code.
- **Semantic** (`sys.*`): roles such as `bg.base`, `fg.secondary`, `money.income`, `budget.over` and `space.inset.card`. This tier is what apps consume.
- **Component** (`comp.*`): only where a component needs its own knob (`button.primary.bg`), and only as aliases to semantic tokens (judgment).
- **Modifiers.** `appearance` ∈ {light, dark, lightHC, darkHC} and `platform` ∈ {ios, macos, watchos, web}: 16 permutations. watchOS has no appearance setting ("Dark Mode isn't supported in visionOS or watchOS", [HIG Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)) and renders dark, but keep its light contexts: Apple asks for light and dark custom colors "even if your app ships in a single appearance mode", for Liquid Glass adaptivity ([HIG Color](https://developer.apple.com/design/human-interface-guidelines/color)). That paragraph names iOS, iPadOS, macOS and tvOS, so applying it to watchOS 26 glass controls is judgment. Platform contexts carry the type ramp, control sizes and radius deltas.
- **Names.** CSS `--ob-bg-base`, TypeScript and the Unistyles theme `bg.base`, Swift `DS.Color.bgBase`, as in [cross-platform-ui-stack](cross-platform-ui-stack.md) §8.1. Apple bindings live in `$extensions["app.onbudget.apple"]`, for example `{ "systemColor": "secondarySystemBackground" }`. The same token's value in each appearance is its web value (§1.4), and the permutation script fails when a bound role lacks one.

- Don't self-host SF on the web. Pointing `system-ui` at the font already installed on the device distributes nothing (judgment, medium-high).
- **Non-Apple web clients.** The web app runs "on any computer" for any self-hoster's household ([PRODUCT.md](../../PRODUCT.md), Users and Operating Context). There `system-ui` is another face with other metrics ("highly dependent on the platform environment", [CSS Fonts 4](https://www.w3.org/TR/css-fonts-4/)), and `ui-rounded` falls back. So either test the web ramp, tabular figures and French wrapping against Segoe UI and Roboto, or bundle one OFL face on the web (decision 3; spike S5 in [cross-platform-ui-stack](cross-platform-ui-stack.md)). The Linux CI image has neither, so pin a font for screenshots (judgment).
- **Mock-ups.** The SF license allows use "solely for creating mock-ups of user interfaces to be used in software products running on Apple's iOS, OS X or tvOS" (SF Compact: watchOS) and bars mock-ups for "software products running on any non-Apple operating system". It adds that "only one user may use the Apple Font at a time" and bars making it "available over a network where it could be run or used by multiple computers at the same time" (§2A–2B, [Apple fonts](https://developer.apple.com/fonts/)). So don't upload SF to a hosted Claude Design system, and don't mock up the web app in SF (judgment, from that text).
- **Numbers.** Use tabular figures for amounts: `.monospacedDigit()` ([doc](https://developer.apple.com/documentation/swiftui/view/monospaceddigit())) and `font-variant-numeric: tabular-nums` (widely available). SF has rounded variants for a softer hero number ([HIG](https://developer.apple.com/design/human-interface-guidelines/typography)). The web `ui-rounded` family works in Safari only ([web-features](https://www.npmjs.com/package/web-features)).

### 2.2 Type scale, Dynamic Type and rem

Semantic roles map to the native text styles on Apple (SwiftUI on the watch; `dynamicTypeRamp` in React Native, per [cross-platform-ui-stack](cross-platform-ui-stack.md)), so Dynamic Type comes for free. Sizes are pt/leading from the [HIG specs](https://developer.apple.com/design/human-interface-guidelines/typography): iOS at the Large default, watchOS at its Large default (40/41/42 mm). The web column is a proposal (judgment): iOS × 16/17, rounded, with a 12 px floor.

- **Web**: sizes in rem only, never px or bare `vw`. react-native-web turns style numbers into px (§1.4), so the generated web theme carries rem strings. `clamp()` only for display roles, so 200 % zoom works ([WCAG 1.4.4](https://www.w3.org/TR/WCAG22/)). Whether `font: -apple-system-body` makes rem follow Dynamic Type in iOS Safari is unverified (spike S3).

### 2.3 Spacing, sizing, layout and breakpoints

- **Space scale** (judgment): a 4 pt base, with tokens 2, 4, 8, 12, 16, 20, 24, 32, 40, 48 and 64. Layout margins come from the system (safe areas, layout guides, size classes) on Apple, never hard-coded ([HIG Layout](https://developer.apple.com/design/human-interface-guidelines/layout)). Web gutters: 16 px compact, 24 px medium, 32 px expanded.
- **Targets**: iOS and watchOS 44×44 pt default (28 minimum); macOS 28×28 (20 minimum) ([HIG Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)). Web: WCAG 2.5.8 requires 24×24 CSS px at AA ([Understanding](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)); use 44 px under `pointer: coarse` (judgment).
- **Web breakpoints**: borrow Material's neutral thresholds: compact < 600, medium 600–839, expanded 840–1199, large ≥ 1200 ([Android](https://developer.android.com/develop/ui/views/layout/use-window-size-classes)). They map to iPhone-like (tab bar), iPad-like (split) and Mac-like (sidebar, then sidebar + inspector) layouts (judgment). Components use container queries, Baseline widely available since 2025-08 ([web-features](https://www.npmjs.com/package/web-features)).

### 2.4 Color

- **Authoring**: primitives in OKLCH, each with a `hex` fallback. Keep UI roles inside sRGB (`core/max-gamut: srgb`, checked in every permutation by the script, §1.2), because the Figma import accepts only sRGB/HSL ([Figma](https://help.figma.com/hc/en-us/articles/15343816063383-Modes-for-variables)) and React Native documents no P3. Allow P3 only for the accent and data-viz highlights. Apple renders Display P3 colorsets. On the web, `oklch()` and `color()` are widely available since 2025-11 ([web-features](https://www.npmjs.com/package/web-features)). Apple: "P3 colors and images appear fine on sRGB displays", but near-identical P3 colors can merge ([HIG Color](https://developer.apple.com/design/human-interface-guidelines/color)).
- **Semantic roles**:
  - Surfaces: `bg.base`, `bg.grouped`, `bg.raised`, `bg.overlay`, `bg.chrome`, `bg.field`.
  - Text: `fg.primary`, `fg.secondary`, `fg.tertiary`, `fg.disabled`, `fg.onAccent`.
  - Borders: `border.separator`, `border.control`, `border.focus`.
  - Accent: `accent.default`, `accent.pressed`, `accent.subtle`.
  - Status: `status.success`, `status.warning`, `status.critical`, `status.info`.
  - Money and budget: `money.income`, `money.expense`, `money.transfer`, `budget.onTrack`, `budget.near`, `budget.over`, `budget.toAssign`, `goal.progress`.
  - Data viz: `dataviz.cat.1–8`, `dataviz.seq.*`, `dataviz.div.*`.
  - Members and households: `member.1–6.fill` and `.onFill`, `member.joint`, `household.test.*` (§2.11).
- **Bind to Apple system colors** where a system role exists (asset catalogs on the watch, `PlatformColor` in the iOS app): background, grouped background, label and separator, mapped to `windowBackgroundColor`, `labelColor` and so on on macOS. Apple says to "prefer the system background colors" so the base-to-elevated dark-mode shift keeps working, and not to repurpose their meanings ([HIG Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode), [HIG Color](https://developer.apple.com/design/human-interface-guidelines/color)). Web values are UIKit's resolved colors (§1.4).
- **macOS accent**: the system replaces the app's accent color unless the user's accent setting is "multicolor" ([HIG Color](https://developer.apple.com/design/human-interface-guidelines/color)), so the accent never carries meaning.
- **Contrast policy (gate)**:
  - WCAG 2.2 (Recommendation, 2024-12-12): text 4.5:1, large text 3:1 (1.4.3), controls, focus and chart marks 3:1 (1.4.11) ([WCAG 2.2](https://www.w3.org/TR/WCAG22/)).
  - Check every declared pair in all four appearances, with the permutation script (§1.2). Apple asks for at least 4.5:1 and, "for custom foreground and background colors", to "strive for a contrast ratio of 7:1, especially in small text", in all appearances ([HIG Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)). So: block below the WCAG minimums, warn below 7:1 for custom text pairs in every appearance, and block below 7:1 for body text in the HC contexts (judgment).
  - Apple's Accessibility Inspector uses WCAG AA values. The HIG names APCA as another "popular standard" ([HIG Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)).
  - **APCA is advisory only.** WCAG 3's contrast algorithm "is yet to be determined" ([WCAG 3 WD](https://www.w3.org/TR/wcag-3.0/)), and `apca-w3` is licensed for "web-delivered and web-based content only", otherwise AGPL ([license](https://github.com/Myndex/apca-w3/blob/master/LICENSE.md)). **High.**
- **Increased contrast**:
  - Watch and widgets: asset-catalog high-contrast variants.
  - iOS app: `DynamicColorIOS`'s `highContrast*` keys and the system colors switch natively. Code that needs the state reads `AccessibilityInfo.isDarkerSystemColorsEnabled()` and the iOS event `darkerSystemColorsChanged`, which RN's source defines and its docs omit ([docs](https://reactnative.dev/docs/accessibilityinfo), [source](https://github.com/facebook/react-native/blob/main/packages/react-native/Libraries/Components/AccessibilityInfo/AccessibilityInfo.js)).
  - Web: `prefers-contrast: more` (widely available since 2024-11), plus `forced-colors` with CSS system colors ([web-features](https://www.npmjs.com/package/web-features)), both in `tokens.css`. react-native-web's `AccessibilityInfo` reports only reduced motion ([source](https://github.com/necolas/react-native-web/blob/0.21.4/packages/react-native-web/src/exports/AccessibilityInfo/index.js)) and its `Appearance` only `prefers-color-scheme` ([source](https://github.com/necolas/react-native-web/blob/0.21.4/packages/react-native-web/src/exports/Appearance/index.js)), so code reads `matchMedia('(prefers-contrast: more)')`.
  - Test with Increase Contrast and Reduce Transparency on, both separately and together ([App Store criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/sufficient-contrast-evaluation-criteria/)).
- **Theme control**: follow the system. Apple advises "avoid offering an app-specific appearance setting" ([HIG Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)). A web-only override is an open question.

### 2.5 Money semantics

- **Amounts come from formatters, never from string concatenation.** A local check on 2026-11-07, with Node 24.22 (ICU 78.3, CLDR 48) and Swift 6.3.3 Foundation agreeing:
  - `fr-FR`: `-1 234,56 €`, with U+202F as group separator and U+00A0 before `€`.
  - `es-ES`: `-1234,56 €`, with no grouping below 10 000.
  - `sv-SE`: `−1 234,56 kr`, with U+2212 as the minus sign.
  - `de-CH`: `CHF-1'234.56`.
  - So: no fixed widths, tabular digits, right-aligned amounts, and integer minor units in the model ([apple-client-stack](apple-client-stack.md)).
- **Roles, all judgment backed by cited guidance**:
  - **Expense**: `fg.primary` with the formatter's sign; no red, because guilt drives quitting ([budgeting-products](budgeting-products.md)).
  - **Income**: `money.income` color plus an explicit `+`.
  - **Transfer**: neutral, with a transfer glyph.
  - **Near limit**: `budget.near`, a percentage label and a glyph.
  - **Over budget**: `budget.over`, `exclamationmark.triangle` (Lucide `triangle-alert`) and text such as "12 € over".
  - **To assign** (zero-based): accent plus label.
- **Never color alone.** Apple's criteria cite red/green status dots as the failing example. They recommend shape, placement or text, keeping chart colors in legend order or labeling marks directly, and testing with the Grayscale filter ([criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/differentiate-without-color-alone-evaluation-criteria/)). Add extra glyphs and patterns when `accessibilityDifferentiateWithoutColor` is on ([doc](https://developer.apple.com/documentation/swiftui/environmentvalues/accessibilitydifferentiatewithoutcolor)). Red's meaning differs between cultures ([HIG Color](https://developer.apple.com/design/human-interface-guidelines/color)).
- **Privacy**: a hide-amounts state on every money component: a prop in the shared app, and `privacySensitive()` with redaction on the watch and widgets ([doc](https://developer.apple.com/documentation/swiftui/view/privacysensitive(_:))). Widgets redact when the device is locked.

### 2.7 Radii, borders, motion

- **Radii**: 4, 8, 12, 16, 24 and full, assigned per role (control, card, sheet). Nested shapes follow inner = outer − inset. Apple: `ConcentricRectangle` and `containerShape` (26 OSes; [doc](https://developer.apple.com/documentation/swiftui/concentricrectangle)). Web: `border-radius`, with `corner-shape: squircle` only as progressive enhancement, since it is not Baseline (Chrome 139 only) ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/corner-shape)).
- **Borders**: one hairline token, 1 physical pixel on Apple (1 / `displayScale`) and 1 px on the web; `border.focus` at 3:1 against its surroundings.
- **Motion tokens**:
  - Durations `fast` 120 ms, `base` 200 ms, `slow` 320 ms, plus two easings as DTCG `cubicBezier`: SwiftUI `timingCurve`, Reanimated `Easing.bezier()` ([withTiming](https://docs.swmansion.com/react-native-reanimated/docs/animations/withTiming/)), CSS `cubic-bezier()`.
  - Springs live in `$extensions` as `{duration, bounce}` with bounce ≥ 0. The generator converts each once to mass 1, stiffness (2π ÷ duration)² and damping (1 − bounce) × 4π ÷ duration, the conversion WWDC23 gives ([Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/)). SwiftUI agrees: `Spring(duration: 0.5, bounce: 0.2)` reports mass 1, stiffness 157.9 and damping 20.1 (Swift 6.3.3 on macOS 26, run locally; negative bounce departs from this closed form). Three outputs:
    - SwiftUI `Spring(duration:bounce:)` (iOS 17 / macOS 14 / watchOS 10, [doc](https://developer.apple.com/documentation/swiftui/spring/init(duration:bounce:))).
    - Reanimated 4.7.1, which Expo SDK 58 bundles ([bundledNativeModules](https://github.com/expo/expo/blob/sdk-58/packages/expo/bundledNativeModules.json)): `withSpring` with `{ mass: 1, stiffness, damping }`. Not its duration mode: that `duration` is "perceptual", the actual one 1.5 times longer, and stiffness is solved numerically to fit ([withSpring](https://docs.swmansion.com/react-native-reanimated/docs/animations/withSpring/), [springUtils.ts](https://github.com/software-mansion/react-native-reanimated/blob/main/packages/react-native-reanimated/src/animation/spring/springUtils.ts)), so its curve differs from SwiftUI's. Its default mass is 4.
    - CSS `linear()` sampled from the same spring, widely available since 2026-06 ([web-features](https://www.npmjs.com/package/web-features)). Reanimated's CSS transitions take the same `linear()` and `cubicBezier()` on iOS and the web ([timing functions](https://docs.swmansion.com/react-native-reanimated/docs/css-transitions/transition-timing-function/)).
    - **High** on the conversion, **medium** that the three curves match on screen (spike S2).
  - Prefer system transitions. Under Reduce Motion (`accessibilityReduceMotion`, `prefers-reduced-motion`), replace movement with crossfades: "Make motion optional" ([HIG Motion](https://developer.apple.com/design/human-interface-guidelines/motion)). Reanimated's default, `ReduceMotion.System`, follows the setting by disabling the animation ([accessibility](https://docs.swmansion.com/react-native-reanimated/docs/guides/accessibility/)). So the presets swap to a crossfade on `AccessibilityInfo.isReduceMotionEnabled()` and `reduceMotionChanged`, which react-native-web maps to `prefers-reduced-motion` (§2.4) (judgment).

### 2.10 Localization and regional formats inside components

- **English and French now, LTR only.** Short strings can expand 200–300 % in translation ([W3C i18n](https://www.w3.org/International/articles/article-text-size)). ### 2.11 Ownership, visibility and households

- **Requirement.** In [`PRODUCT.md`](../../PRODUCT.md), "each person decides which accounts and budgets are private or shared", data is "private by default and shared by choice", and when a member pays for someone else "the category counts only the member's share; the rest becomes an expected reimbursement". The owner also keeps a test household next to the real one. [`budgeting-products.md`](budgeting-products.md) names attribution inside the plan, and privacy, as the couples' unmet need (TL;DR 3; MVP items 2, 3, 5 and 8).
- **Words.** [`GLOSSARY.md`](../../GLOSSARY.md) reserves *owner* for the instance owner and says sharing "is about who sees something, not who holds it". So components say *member* (whose it is), *joint* (held by several members) and *visibility* (who sees it), and the owner chip is `MemberChip`. Per-item attribution has no glossary term yet (judgment).
- **Precedents.**
  - Monarch's Shared Views give every account and transaction a "Shared" or "Individual" owner. Transactions inherit their account's, an optional column shows "the icon and drop-down to change the owner", and rules can "split a transaction and assign different owners to each split". But "all accounts are visible to all household members" ([help](https://help.monarch.com/hc/en-us/articles/42228648365076), updated 2026-10-19).
  - Honeydue lets each partner pick, per account, "Share both balances and transactions", "Share balances only" or "Nothing at all" ([help](https://support.honeydue.com/en/articles/3179542-will-my-partner-see-my-bank-account-balances-and-transactions)).
  - Tricount: "Enter the total and the person who paid", then "change each person's share of the expense" ([features](https://tricount.com/expense-tracker-features/custom-split-expenses)).
  - Stripe opens sandboxes from its account picker, and "the banner at the top of the Dashboard indicates that you're in a sandbox" ([docs](https://docs.stripe.com/sandboxes/dashboard/manage)). [`self-hosting.md`](self-hosting.md) §5.2 already gives a `kind=test` household a banner.
  - Apple asks for "succinct phrases that summarize the sharing permissions", such as "Only invited people can edit" ([HIG Collaboration and sharing](https://developer.apple.com/design/human-interface-guidelines/collaboration-and-sharing)).

| `ScopePicker` | `me`, a member, `household` | Safe to spend and budgets per person and for the household (budgeting-products MVP 5); the watch glance's `me` and `shared` scopes ([watchos-app](watchos-app.md)) |
| `HouseholdSwitcher` | the signed-in member's households; hidden when there is one | Sidebar header on the Mac and the web, account sheet on the iPhone |
| `TestHouseholdBanner` | always on in a test household | Glyph plus "Test household", never "sandbox" or "demo" (`GLOSSARY.md`); a badge on the watch glance and widgets |

- **Two kinds of privacy.** Visibility decides who in the household sees data; the hide-amounts state (§2.5) hides it from whoever looks at the screen. They stay separate props.
- **Watch.** Complications may render tinted in one color ([HIG Color](https://developer.apple.com/design/human-interface-guidelines/color)), so the watch tells `me` from `shared` with `person.fill` and `person.2.fill` plus words, never with member colors.
- **Open.** Whether a partner may see that a private account exists is undecided ([budgeting-products](budgeting-products.md) open question 4). `AccountRow` gets a `hiddenFromViewer` placeholder only if the owner says yes.
- **Tests.** Specs add `twoMembers`, `joint`, `private`, `balancesOnly`, `testHousehold` and `longName` (French names with diacritics) to their matrices.
- **Medium**: the need and the precedents are sourced; the tokens and components are judgment, to check in spike S8.

### 4.3 How impeccable (installed 4.8.0, the latest skill release) consumes it

- **Loading.** `impeccable context` loads PRODUCT.md, DESIGN.md, the surface brief and the native-platform guidance ([SKILL.md](https://github.com/pbakaus/impeccable/blob/main/plugin/skills/impeccable/SKILL.md)).
- **Front matter is normative.** Motion, shadows and breakpoints, which the schema rejects, go in the `.impeccable/design.json` sidecar. impeccable writes DESIGN.md through its documenter at the finish of a new visual world, and never overwrites an existing one without asking ([document.md](https://github.com/pbakaus/impeccable/blob/main/plugin/skills/impeccable/reference/document.md)).
- **Detector hook.** It scans only web file types (`.tsx`, `.jsx`, `.html`, `.css`, `.ts`, `.js`, …) and flags design-system drift, e.g. `design-system-font-size` against DESIGN.md's ramp ([hooks.md](https://github.com/pbakaus/impeccable/blob/main/plugin/skills/impeccable/reference/hooks.md)). It skips its per-edit and Stop passes entirely, web files included, when the platform is `ios`, `android` or `adaptive` (`is_native_platform` in [hook_lib.rs](https://github.com/pbakaus/impeccable/blob/skill-v4.8.0/crates/hook/src/hook_lib.rs), used in [hook.rs](https://github.com/pbakaus/impeccable/blob/skill-v4.8.0/crates/hook/src/hook.rs); unchanged in engine 0.1.19).
- **Native platforms.** For `ios`, `android` and `adaptive`, the no-argument menu doesn't lead with `live`, `generate` or `detect` and skips its own detect run ([routing.md](https://github.com/pbakaus/impeccable/blob/main/plugin/skills/impeccable/reference/routing.md)), and `generate` declines ([generate.md](https://github.com/pbakaus/impeccable/blob/skill-v4.8.0/plugin/skills/impeccable/reference/generate.md)). Native audits read the source and score against `ios.md`, or against `ios.md` and `android.md`, "both for `adaptive`" ([audit.native.md](https://github.com/pbakaus/impeccable/blob/skill-v4.8.0/plugin/skills/impeccable/reference/audit.native.md)). `ios.md` expects system text styles, semantic colors and SF Symbols, and says not to mix in a web icon set ([ios.md](https://github.com/pbakaus/impeccable/blob/main/plugin/skills/impeccable/reference/ios.md)).
- **Manual detect.** The `impeccable detect` CLI has no platform gate, and `hook.enabled` "only controls automatic hook execution, not manual CLI scans" ([hooks.md](https://github.com/pbakaus/impeccable/blob/main/plugin/skills/impeccable/reference/hooks.md)). So CI can run `impeccable detect --json <web paths>` whatever the platform.
- **Consequence.** `PRODUCT.md` now says `Platform: adaptive`: no automatic hook anywhere, and Android guidance in audits of a product with no Android app. Only `web` turns the hook on, and it drops the native references. impeccable reserves `adaptive` for "one product that genuinely adapts its design language per OS", and "a native wrapper around a website does not make its design language native" ([init.md](https://github.com/pbakaus/impeccable/blob/skill-v4.8.0/plugin/skills/impeccable/reference/init.md)). PRODUCT.md takes one value, so the owner decides (decision 5); the CI detect step works with any value.

**Pipeline.**
1. `mise run ds:build` runs `tz build` and writes every output (generated files are committed).
2. `mise run ds:check` runs token lint, the permutation script, the CVD script, `design.md lint`, the drift diff, spec parity and the icon map check.
3. In CI, a Linux job runs those checks plus ESLint, Storybook tests (Vitest + a11y on react-native-web), Playwright screenshots of the web build and `impeccable detect --json` on the web paths. A GitHub-hosted macOS job (`macos-26`, or `xcode-27` when Xcode 27 is needed), path-filtered to `packages/design-system/`, `app/` and `apple/`, runs SwiftLint, Maestro screenshots of the iOS app, widget and watch snapshots, and UI smoke tests with `performAccessibilityAudit`. It costs nothing while the repo is public; no self-hosted runner is used, and Xcode Cloud only archives releases ([factory](factory-ci-quality.md) TL;DR 1). Both jobs fill the `ui` slot of `factory-ci-quality.md`'s pipeline, behind its single `gate` check.
4. Static docs are published per release.

| Layer | Choice (version, 2026-11-07) | Trade-off |

### Foundations checklist

- [ ] **Color**: OKLCH primitives with hex fallbacks; semantic roles (§2.4); four appearances for every custom role; Apple system bindings with UIKit-resolved web values; ≥ 4.5:1 text and ≥ 3:1 non-text in all appearances, aiming for 7:1 on custom text pairs; P3 only for accent and data viz.
- [ ] **Ownership**: six member slots, joint and test-household roles; `MemberAvatar`, `MemberChip`, `VisibilityBadge`, `SplitBreakdown`, `ScopePicker`, `HouseholdSwitcher`, `TestHouseholdBanner`; identity never by color alone.
- [ ] **Money**: sign from the formatter; glyph and text for status; neutral expenses; hide-amounts state; tested with Grayscale and Differentiate Without Color.
- [ ] **Type**: role ramp per platform (§2.2); tabular digits; 200 % (watch 140 %) without truncating digits; French diacritics not clipped; web checked against non-Apple fonts, or one bundled face.
- [ ] **Space and layout**: 4 pt scale; system margins on Apple; web gutters and breakpoints; target sizes (44 pt, 24/44 px).
- [ ] **Surfaces**: base, grouped, raised, overlay, chrome; dark-mode elevation by lightness; Liquid Glass only for system chrome; web chrome opaque under high contrast.
- [ ] **Shape**: radius scale, concentric rule, hairline token, 3:1 focus ring.
- [ ] **Motion**: three durations, two easings, two springs, each spring one set of physics parameters for SwiftUI, Reanimated and CSS; crossfade under Reduce Motion; no motion-only meaning.
- [ ] **Icons**: `icons.yaml` complete for SF and Lucide; custom glyph pipeline; Icon Composer app icon with its appearances.
- [ ] **Data viz**: 8 categorical, sequential and diverging palettes, CVD-validated in both themes; direct labels; forecast style.
- [ ] **Haptics**: semantic event map; optional; visual equivalent on the web.
- [ ] **Locale**: EN/FR strings, pseudo-locale, formatter-only money and dates, pinned locale and time zone in tests.
- [ ] **Watch**: renders dark (no appearance setting), with light and HC variants still generated for Liquid Glass; SF Compact roles; tinted complications.

### Trade-offs the owner must accept

- **Shared over native** ([ADR 0002](../adr/0002-one-ui-codebase-native-watch.md)). The iPhone, Mac and web apps render through React Native, so Liquid Glass and SF Symbols appear only where Expo exposes them, and the web shows each OS's font. Only the watch and widgets are fully native.
- **Two color mechanisms.** Native color objects on iOS, CSS variables on the web. One generator and the permutation script keep them equal; Unistyles alone can't, since it switches only `light` and `dark` on the web.
- **We own the glue.** Code generation plugins, and generated files committed to the repo.
- **Figma stays downstream.** Without Enterprise or Tokens Studio, tokens can't be authored in Figma, drift checks need a manual export, and Code Connect covers one framework (React).
- **Beta and alpha tools.** Claude Design's design systems are beta, and those made in its standalone app must move before it closes on 2026-12-14. DESIGN.md is alpha. Terrazzo's Swift plugin is experimental and resolver-blind, hence our own.
- **System fonts mean a quieter brand**, and a web app that looks slightly different on each OS. A custom face can come later, at the cost of manual Dynamic Type work.

## Open questions and spikes

**Decisions for the owner**
1. Mac styling. [cross-platform-ui-stack](cross-platform-ui-stack.md) picked B (worth recording in an ADR), and Unistyles 3 doesn't support react-native-macos. Keep the Mac on the Dock web app or the iPad app, which reuse the web and iOS outputs, and style a later react-native-macos build with plain `StyleSheet` over the same generated themes?
2. Will anyone design in Figma? If not, skip it entirely and use Claude Design plus code.
3. Brand: an accent color, a typeface policy for the web (each OS's `system-ui` face, or one bundled OFL face), a custom display face, and a name for the system.
4. Theme control: system-only (Apple's advice), or a web-only override?
5. impeccable `Platform`: PRODUCT.md says `adaptive`, which turns the hook off everywhere and adds Android guidance to audits. Under B the shared app is React Native, not a web app in native shells, so `web` doesn't fit: keep `adaptive`, or set `ios`, and rely on the CI detect step?
6. The watch has no light/dark setting and renders dark. A custom light theme is possible but non-standard, and Apple's watchOS advice is to use background color "when you have something to communicate" ([HIG Color](https://developer.apple.com/design/human-interface-guidelines/color)). Is a dark-only watch acceptable for "light and dark on every app"?
7. Ownership display: may members pick their color slot, may a partner see that a private account exists (budgeting-products open question 4), and does the test-household banner tint the whole chrome or only a top band?
